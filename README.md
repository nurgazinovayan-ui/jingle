# Jingle — онлайн музыкальный плеер

Ваш личный музыкальный сайт на [Vercel](https://vercel.com). Вы загружаете треки,
а любой человек по ссылке открывает сайт и слушает их онлайн.

- Файлы хранятся в **Vercel Blob** (облачное хранилище Vercel).
- Загружать и удалять треки может только тот, кто знает пароль (`ADMIN_PASSWORD`).
- Слушать может любой по ссылке, вход не нужен.

## Возможности

- Плейлист с поиском и длительностью треков
- **Зациклить плейлист**: после последнего трека снова играет первый (включено по умолчанию)
- **Повтор трека**: один трек по кругу
- **Перемешать**
- Играть / пауза, предыдущий / следующий, перемотка, громкость
- **Поделиться**: ссылка на весь плеер или на конкретный трек (`/?t=<id>`)
- Загрузка нескольких файлов сразу, drag & drop, прогресс; название и исполнитель
  заполняются из имени файла «Исполнитель - Название.mp3», их можно поправить перед загрузкой
- Управление с клавиатуры, наушников и экрана блокировки телефона (Media Session API)
- Запоминает громкость, режимы, последний трек и позицию

## Как запустить на Vercel (5 минут)

1. **Импортируйте репозиторий**: [vercel.com/new](https://vercel.com/new), Framework Preset: *Other*,
   остальные настройки оставьте по умолчанию → **Deploy**.
2. **Подключите хранилище**: в проекте откройте **Storage** → **Create** → **Blob**,
   выберите доступ **Public** и подключите хранилище к проекту.
   Vercel сам добавит переменную `BLOB_READ_WRITE_TOKEN`.
3. **Задайте пароль**: **Settings** → **Environment Variables** → добавьте
   `ADMIN_PASSWORD` = ваш длинный пароль.
4. **Передеплойте**: **Deployments** → у последнего деплоя **⋯** → **Redeploy**
   (переменные подхватываются только при новом деплое).
5. Откройте сайт → **Войти** → введите пароль → загружайте треки.
6. Нажмите **Поделиться** и отправьте ссылку друзьям.

## Как это устроено

```
index.html, styles.css, app.js — сайт (без фреймворков и сборки)
api/tracks.js   — GET: список треков (публично); POST: обновить плейлист; DELETE: удалить трек (по паролю)
api/upload.js   — выдаёт браузеру токен для загрузки файла прямо в Vercel Blob (по паролю)
api/auth.js     — проверка пароля и настроек
lib/            — общий код функций (lib/manifest.js — плейлист в playlist.json)
data/playlist.js — необязательные «постоянные» треки по внешним ссылкам
vendor/blob-client.js — собранный клиент @vercel/blob для браузера
```

Файл загружается из браузера **напрямую в Blob**, поэтому лимит 4.5 МБ на запрос
к функциям Vercel не мешает. Ограничение на файл — 200 МБ (меняется в `api/upload.js`).

Название и исполнитель хранятся прямо в имени файла в хранилище, так что база данных не нужна.

### Экономия операций Blob

Список треков хранится одним файлом `playlist.json` в Blob (`lib/manifest.js`):

- **Слушатели** читают только `playlist.json` через CDN. Попадание в кэш бесплатно,
  промах — дешёвая «простая» операция. Дорогие «сложные» операции не тратятся.
- **Администратор:** после загрузки или удаления плейлист пересобирается по реальным файлам
  в хранилище (1 `list` + 1 `put`), поэтому он не может «разъехаться» с файлами.
- Сам ответ `/api/tracks` ещё и кэшируется на CDN Vercel на 60 секунд.

Новый трек появляется у слушателей в течение 1–2 минут, а у вас — сразу.
Просмотр хранилища в панели Vercel тоже тратит «сложные» операции, поэтому лучше не открывать его лишний раз.

### Лимиты бесплатного тарифа

У Vercel Blob на тарифе Hobby есть месячные лимиты на объём хранилища и трафик.
Актуальные значения смотрите в [документации Vercel Blob](https://vercel.com/docs/vercel-blob/usage-and-pricing).

## Обновление клиента @vercel/blob

`vendor/blob-client.js` собирается из пакета `@vercel/blob`. После обновления пакета пересоберите его:

```bash
npm run build:vendor
```
